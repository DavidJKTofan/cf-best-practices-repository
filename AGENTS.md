## Frontend design and maintenance

- Keep `AGENTS.md` and `README.md` synchronized with implementation and verification limits whenever behavior, setup, or design rules change.
- Preserve the owner's simple, clean, minimal reference UI: neutral light/dark surfaces, restrained orange accents, compact system-font headings, simple result rows and native form/disclosure controls. No oversized serif marketing headlines, decorative rotated panels, or empty placeholder hubs.
- Use these exact stacks; no remote fonts:
  ```css
  --font: system-ui, -apple-system, 'Segoe UI', Roboto, 'Helvetica Neue', Arial, sans-serif;
  --mono: ui-monospace, SFMono-Regular, Menlo, Consolas, 'Liberation Mono', monospace;
  ```
- Keep Astro styles in `src/styles/field-guide.css` visually aligned with the existing static/dashboard `public/style.css`. Bound listing width to 1440px and reading width to 1120px on large/4K screens; do not stretch prose across a monitor.
- Omit empty sections, headings, contents links, source lists, family/outcome journeys and unused facet groups **server-side**, not just with CSS. Preserve selected zero-result filters so they remain visible and clearable. Keep necessary empty-search/error states and honest unknown freshness/applicability metadata.
- Reading-page contents and extra filters use native disclosures; `public/contents.js` only collapses contents on small screens. All reading/navigation/filtering works without JavaScript. Code may scroll internally, never widen the viewport.
- Recorded Category/Feature/Domain/Level/Impact/Difficulty filters stay visible when populated or selected, separate from native family/product/outcome taxonomy. Keep labeled Domain-color pills/legend (Security/red, Performance/blue, Reliability/green, General/gray), neutral Category/Feature pills and clearable filter chips. `legacyClassification`/`data.legacy` are read-time published-legacy projections, null/empty for native content; do not infer taxonomy or fetch full bodies for labels/facets. [Restoration/local and live evidence](docs/phase6/filter-restoration.md) is not future deployment approval.
- Catalog/family live filtering (`public/catalog-search.js`) progressively enhances the same bounded SSR GET forms: 350 ms text debounce, immediate selects, page reset, latest-request-wins/IME/timeout protection, focus/caret/disclosure and metadata/history preservation. Keep native Search/pagination/clear links usable, including after enhancement failure. Pagination bounds responses, not substring/count/deep-offset query cost; benchmark before changing search/cursor contracts. See [scalability and private-copy evidence](docs/phase6/scalability-and-production-readiness.md) and [scoped production verification](docs/rollout-2026-10-31.md); subsequent remote changes still need explicit approval.
- Check mobile (320/390px), tablet (768px), desktop (1440px) and 4K (3840px), both themes, keyboard focus, no-script forms/reading, and code/copy behavior after meaningful frontend changes. Record targeted browser evidence separately from full accessibility/cross-browser certification and from live release gates.

## Invariants

- **Keep file assets free; scope document routing.** `assets.run_worker_first` explicitly lists `/`, `/index.md`, `/catalog`, `/catalog.md`, `/families/*`, `/practices/*`, `/sitemap.xml`, `/llms.txt`, `/llms-full.txt`, `/api-docs`, `/api/*`, and `/dashboard/api/*`. The document exceptions are required for server rendering and Markdown negotiation and incur Worker invocations. CSS, JS, images, and static discovery files stay asset-first/free. Do not set `run_worker_first: true` or enable Workers Cache on `default` ([pricing](https://developers.cloudflare.com/workers/cache/#pricing)).
- **Reads go through `PublicReads`.** The uncached default entrypoint rate-limits, then forwards public GET/HEAD reads via `ctx.exports.PublicReads.fetch()`. API routes go in `READ_ROUTES`; document routes in `isPublicContent`/`servePublicContent`, plus the explicit Worker-first list. Every D1-derived representation carries the shared `practices` cache tag (taxonomy uses `taxonomy`).
- **Reads use `withSession('first-primary')`.** Cache fills right after a write-triggered purge must not come from a lagging read replica, or stale data is cached for the whole edge TTL.
- **Writes must purge.** Purges are scoped per entrypoint, so writes call the `PublicReads.purgePractices()` RPC method after the D1 write. `wrangler dev` does not emulate Workers Cache (`ctx.cache` is undefined); verify `Cf-Cache-Status` after deploying.
- **Writes live under `/dashboard/api/*` only.** That path is behind Cloudflare Access, and the Worker validates the `Cf-Access-Jwt-Assertion` JWT (`ACCESS_TEAM_DOMAIN`, `ACCESS_AUD`). Never add write routes under `/api/`.
- **Editorial login is not authorization.** Typed editorial routes additionally require private `EditorialRoles` grants for the verified stable actor hash; deny unknown actors and never trust caller role/email claims. All contributors are excluded from review/publication, approval is exact-version, edits/rebases invalidate review, and publication checks the base pointer and current reviewer grant transactionally. Retain private workflow/receipt state in recovery backups, never seeds. Preview HTML/Markdown bypass public cache and remain private/no-store/noindex. Do not provision live grants without owner approval.
- **Creation must be durably idempotent.** Require an actor-scoped `Idempotency-Key`; practice and `PracticeCreations` receipt commit in one D1 batch. Only retry application-idempotent writes. Preserve receipts; exclude them from public seeds but include them in private backups. Same-key/different-data requests return 409. Replays attempt the same purge as initial writes. Never log tokens or raw retry keys.
- **Bound JSON before buffering.** Count actual streamed bytes, cancel above 64 KiB, and do not trust `Content-Length`. Keep malformed UTF-8, multibyte, missing/misleading-length, lost-commit-response, concurrent retry, and transaction-rollback tests.
- **Schema changes = new migration file.** Never edit an applied migration. Run `PRAGMA optimize` after index changes (`create_d1_schema.sh` does).
- **Phase 2 publication boundaries.** Only a matching `CatalogPublications` record can be selected by an entry's published pointer. Keep bodies/sources/taxonomy frozen after publication, including against SQLite `REPLACE`. Legacy conversions are deliberately blocked until an explicit v1/document adapter is reviewed. Preserve both numeric ID high-water marks and the unchanged v1 insertion/receipt SQL; native reservations must never collide with old-app inserts. Catalog labels/aliases are public registry data, not a place for private editorial notes. Public seeds contain only current public snapshots; `CatalogDrafts`, unselected revisions, reservations, and `PracticeCreations` remain private.
- **Content changes = re-runnable SQL in `data/`** (not migrations, which tests apply to an empty database). Validate with `--local` first; obtain approval before `--remote` writes. Direct D1 edits bypass the cache purge; redeploy or account for the one-hour freshness plus 24-hour stale-while-revalidate window. Purges never clear browser caches.
- **Content must be sourced and plan-aware.** Verify fields, functions, phases, actions, and prerequisites against current docs. Preserve practice IDs. Dry run validates configuration, not traffic matches. Log availability is product/phase-specific (request-phase custom/rate limiting Log requires Enterprise); browser challenges are unsuitable for APIs. Apply the data file twice to check idempotency (including `updated_at`), then refresh `initial_data.sql` only after remote application. Record fact-verification dates separately from editorial `updated_at` and distinguish Early Access/announcement-only guidance from validated deployment examples.
- **Never set `remote: true` on the `DB` binding.** Local development must not touch production data.
- **Rehearse remote D1 changes on a production copy.** Production tables predate the migrations, and local/test databases are built from them, so a change that passes locally can still fail remotely. Export with `npx wrangler d1 export DB --remote --output=/path/outside/repository/prod.sql`, load it with `--local --persist-to=<private-state>`, and apply migrations and data files there first. Take a Time Travel bookmark (`npx wrangler d1 time-travel info DB`) before approved remote writes. Keep full backups/bookmarks private; only the catalog-only seed export belongs in the repository.
- **Report caught errors with `console.error(err)`** (the error object, not a string) so [Workers Issues](https://developers.cloudflare.com/workers/observability/issues/) can group them by exception and stack.
- **Public SEO and AI retrieval are intentional.** Allow public HTML indexing and AI answer retrieval: `search=yes, ai-input=yes, ai-train=no`. Keep dashboard/404 pages and JSON API responses `noindex`; do not apply a site-wide noindex. `robots.txt` allows public API reads, blocks `/dashboard` and `/cdn-cgi/`, and blocks training crawlers separately from search/user agents. Zone-managed robots and bot blocking must agree with this policy.
- **Preserve owner-approved security policy.** Respect the published crawler policy and existing account-level client restrictions. Use validated Bot Management fields such as `cf.bot_management.detection_ids` for crawler identification; do not infer identities from generic labels, shared fingerprints, or an entire AI Crawler category. Scope exceptions to public GET/HEAD/OPTIONS on the intended hostname, excluding dashboard and `/cdn-cgi/`, and exclude blocked identities from exceptions. Preserve terminating blocks before exemptions and skip only the responsible mitigation. Inspect the target configuration and confirm changes with the owner, then dry-run each mutation before applying it; validation does not establish real traffic matches. See [deployment guidance](docs/agent-readiness.md#deployment-guidance).
- **Keep documentation public-safe.** Use generic examples or placeholders for deployment-specific identifiers. Keep live security-rule inventories, exact production expressions and thresholds, non-public detection mappings, raw telemetry, and recovery bookmarks out of public documentation.
- **Content must work without JavaScript.** Render homepage links/summaries and complete `/practices/{id}` pages from D1. Preserve old `/#practice-<id>` anchors, but use stable practice paths for canonical citations. Include accurate metadata, escaped JSON-LD, and sourced freshness dates. Sitemap lists canonical HTML URLs only, not filters, APIs, Markdown aliases, or infrastructure paths.
- **Negotiate representations safely.** `/`, `/catalog`, `/families/{slug}`, `/practices/{id}`, and `/api-docs` default to HTML and negotiate explicitly preferred `text/markdown` (respect q values/exclusions). Set `Vary: Accept` on both variants. Normalize Accept before cached reads; only new catalog/family listings retain canonical effective query state. Existing documents still drop UI queries. Explicit `/index.md`, `/catalog.md`, `/families/{slug}.md`, `/practices/{id}.md`, and `/llms-full.txt` remain Markdown regardless of Accept. Finalize Astro headers after the adapter without buffering; never cache errors/cookies or reuse shell validators.
- **Keep discovery accurate.** Maintain `/llms.txt`, `/llms-full.txt`, `/sitemap.xml`, `/openapi.json`, `/api-docs` (+ `.md`), `/auth.md`, RFC 9727 `/.well-known/api-catalog`, `/.well-known/ai-catalog.json`, and the agent skill/index. After editing SKILL.md, update its SHA-256 digest (`shasum -a 256 public/.well-known/agent-skills/read-practices/SKILL.md`); tests verify the served bytes. Public reads require no credentials. Publish auth/protocol metadata only for implemented services. WebMCP is feature-detected and exposes only read-only search.
- **Frontend safety.** Render client data with DOM APIs and `textContent`; never `innerHTML` with API data. Server HTMLRewriter insertion accepts only escaped renderer output; escape text/attributes, allow only HTTP(S) source URLs, and escape `<` in JSON-LD. Markdown must escape prose and use fences longer than any backtick runs in stored configuration.
- Static asset headers belong in `public/_headers`; Worker responses set headers in code.

## Debugging

Use the right tool for the environment:

| Need                                          | Tool                                                                                                                                                 |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Local data, logs, and traces (`wrangler dev`) | [Local Explorer](https://developers.cloudflare.com/workers/local-development/local-explorer/) UI at `/cdn-cgi/local/explorer` (press `e`) or its API |
| Production errors                             | Workers Issues (dashboard > Worker > Issues), enabled via `observability.issues` in `wrangler.jsonc`                                                 |
| Production logs and traces                    | Workers Observability MCP server                                                                                                                     |
| Account configuration (Access app, zone)      | Cloudflare API MCP server (read before changing; confirm writes with the owner)                                                                      |
| Product facts                                 | Cloudflare Documentation MCP server                                                                                                                  |

Local Explorer API (OpenAPI spec: `curl http://localhost:8787/cdn-cgi/local/explorer/api`):

```bash
# Run SQL against the local D1 database (single statement, or {"batch": [...]})
# Set DATABASE_ID to the database identifier shown in Local Explorer.
curl -X POST "http://localhost:8787/cdn-cgi/local/explorer/api/d1/database/${DATABASE_ID}/raw" \
  -H 'Content-Type: application/json' -d '{"sql":"SELECT COUNT(*) FROM BestPractices"}'

# Query captured traces and logs with read-only SQL (tables: spans, logs; root spans have parent_id IS NULL)
curl -X POST http://localhost:8787/cdn-cgi/local/explorer/api/local/observability/query \
  -H 'Content-Type: application/json' \
  -d '{"sql":"SELECT name, duration_ms, json_extract(json(attributes), ?) FROM spans WHERE parent_id IS NULL ORDER BY start_ms DESC LIMIT 10","params":["$.\"url.full\""]}'
```

Local caveats: `wrangler dev` rewrites `request.url` to the production hostname, sets `CF-Connecting-IP` to a loopback address, and does not emulate Workers Cache (no `Cf-Cache-Status`, `ctx.cache` is undefined). It also rewrites Link response URLs to localhost while HTML canonicals retain the production URL; local Lighthouse reports this canonical mismatch. Verify canonical agreement on the deployed hostname.
