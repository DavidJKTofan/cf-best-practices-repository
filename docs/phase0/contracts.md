## Protected creation (must remain byte-for-byte compatible in meaning)

`POST /dashboard/api/practices` is the sole write route. Public `/api/*` does not gain mutations. The edge Access application is deployment configuration, and the Worker also validates `Cf-Access-Jwt-Assertion`.

- `src/access.ts`: RS256 signature via issuer JWKS, issuer, audience, temporal claims, stable user subject or signed service `common_name`. Only public verification keys are cached. Local bypass requires explicit opt-in **and** loopback IP; never deployed by the prototype.
- `src/request-body.ts`: exact JSON media type (parameters allowed), early length rejection plus actual streamed-byte counting, 64 KiB maximum, cancellation without trusting the producer, fatal UTF-8 decode. No unbounded `.json()` before validation.
- `practice-validation.ts`: fixed normalized key order, existing enum/text/ID/source rules. Preserve `null` treatment, trimming, NUL removal, and optional fields for old receipt recovery.
- Actor/key operation hash is SHA-256 of `['create-practice:v1', subject, key]`; payload hash is SHA-256 of canonical normalized JSON. Do not change either namespace or ordering during a framework refactor.
- Insert practice + receipt in one D1 batch transaction. Same actor/key + same normalized payload -> original 201/ID; changed data -> 409. Different actors do not collide. Never log raw keys/tokens.
- Retry only application-idempotent batches on selected transient failures with bounds/backoff; do not retry permanent constraints.
- Await purge attempt after commit and on replay; failure does not undo a committed practice. Keep receipts in private backups, not public seeds.
- Write/error responses are no-store; no public write CORS. GET/OPTIONS on creation are not read preflight aliases.

Existing evidence: `test/access.spec.js`, `test/request-body.spec.js`, `test/index.spec.js` cover valid/invalid JWTs, service identity, local opt-in, malformed and oversized input, concurrency/conflicts, lost-commit response, retries, rollback, actor isolation, receipt retention and replay purges. Prototype tests add routing/build evidence with a local JWKS server and signed JWTs; they do not authenticate against a live Access application.

## Discovery, indexing, and stored-content safety

- Maintain `/sitemap.xml` (canonical HTML only), `/llms.txt`, `/llms-full.txt`, `/openapi.json`, `/api-docs` + `.md`, `/auth.md`, `/.well-known/api-catalog`, `/.well-known/ai-catalog.json`, skill/index/digest, feature-detected read-only WebMCP.
- Public reads anonymous; public HTML indexable; dashboard/404/JSON noindex. Preserve `search=yes, ai-input=yes, ai-train=no` and existing crawler restrictions. Prototype is deliberately noindex and must not be deployed.
- Existing tests verify catalogs and skill digest against served bytes, public methods/CORS, API paths and filter definitions, source/metadata/canonical links, sitemap dates, HTML escaping, JSON-LD parseability and Markdown fences.
- Astro automatically escapes expressions but is not permission to use arbitrary stored HTML/MDX. Keep source protocol validation; no active `javascript:` links. No server maps or SQL/receipts/private config in client assets.

## Coverage gaps and required future additions

**Discovered baseline defect — long search (corrected locally after Phase 6 tooling):** `normalizeApiRequest` accepts 200 JavaScript UTF-16 code units, but [`D1 LIKE/GLOB patterns are limited to 50 bytes`](https://developers.cloudflare.com/d1/platform/limits/). The original `listPractices` added `%` around the escaped search; even 49 plain ASCII characters exceeded the limit. Multibyte characters and wildcard escaping consumed more bytes. The Phase 0 built proof reproduced HTTP 500/no-store; this was not a desired contract or a framework regression. A later separate [local hardening change](../phase6/development-hardening.md) replaces LIKE with bound per-field `instr(lower(…), lower(?))`, preserving the same normalization/cache keys, six fields and case semantics without additional truncation. Runtime/built/prototype regressions now expect successful full-length literal searches; the prototype retains the direct D1 LIKE-limit proof. **Not deployed; independent review and release gates remain open.** The inventory above records the historical baseline, not the corrected implementation.

1. Edge cache hits/purges/replica consistency and deployed Access coverage need approved staging/live checks; neither workerd nor a dry run proves them.
2. Authenticated browser retry after reload, denied edge login/service-token flow, and real concurrent traffic still require deployment-level evidence (see existing rollout notes).
3. v2 publication filtering, revision concurrency, taxonomy relationships, faceted pagination and cache dependency tests do not exist yet. Add before implementation ships.
4. The isolated proof is not a behavior-identical replacement: it renders a limited homepage, has no final canonical/structured metadata or dashboard UI, and deliberately noindexes HTML. Existing production discovery tests remain authoritative; a Phase 3 frontend must pass the full contract matrix.
5. Automated keyboard/screen-reader/mobile/no-JS journey and performance evidence is still Phase 3/6 work. Wireframes are not accessibility certification.
6. Schema validation of the future body types and production-copy rehearsals are not satisfied by schema sketches or empty test databases.
