## Local validation and release

`npm run content:check` builds all migrations plus the production seed in offline SQLite, validates integrity/taxonomy/sources/ratings/limits, applies each active data patch twice with distinct clocks, and compares all stored data, timestamps, and sequences. A self-test proves unconditional timestamp updates are detected. Workerd tests separately validate D1 transaction/retry behavior. These checks do **not** substitute for a rehearsal against the current production schema and data.

Before an approved remote application:

1. Export the **full** current D1 database to a private directory outside the repository. Full backups include `PracticeCreations` after migration 0005; public seed refreshes deliberately exclude it.
2. Import into an isolated local D1 state with `--local --persist-to=<private-state>`, apply pending migrations there, and apply `data/copyable-expressions.sql` followed by this patch. Repeat this patch and compare all rows/timestamps/sequences. Verify required taxonomy and the five corrected IDs. Run `PRAGMA foreign_key_check` and `PRAGMA optimize`.
3. Follow the [D1 best practices](https://developers.cloudflare.com/d1/best-practices/) and [import/export guide](https://developers.cloudflare.com/d1/best-practices/import-export-data/). Check live schema drift and import limitations; never replace the remote database with the seed or a locally regenerated snapshot.
4. Obtain owner approval and take a fresh Time Travel bookmark; store it privately. Apply pending migrations before deploying dependent code. Apply the content patch, verify content, and invalidate all cached representations (direct SQL bypasses the write purge RPC).
5. Verify live reads, cache variants, retry/conflict behavior, and Access protection. Only then refresh `initial_data.sql` using the catalog-only export command. Retain private backups and rollback instructions; do not publish receipts, raw telemetry, or recovery identifiers.
